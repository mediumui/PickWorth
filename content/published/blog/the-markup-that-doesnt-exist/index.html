The markup that does not exist

The open-source coding agent's real advantage is not that it is as good as the frontier CLI. It is that between you and the work there is no subscription, and the only line on the bill is the tokens.

29 October 2026 PickWorth Editorial

The short answer. The strongest argument for a free, open-source coding agent is not quality — it is the markup you stop paying. A terminal agent like Aider or Cline charges zero for the tool itself; you pay only for model tokens, and no provider's per-seat subscription sits between you and the work. When that constraint is cost-per-task, the open tool is not a downgrade, it is the one that is priced honestly.

What do I actually pay when I use an open-source coding agent?
Only the model tokens. The tool itself is free, so the cost is the underlying inference — which you can run on any provider's API, or on a local model at zero marginal cost. There is no per-seat subscription layered on top.
Is the open tool worse than the frontier CLI?
On raw capability it trails a top frontier CLI in some autonomous tasks, but on day-to-day multi-file work the gap is smaller than the price gap. For most developers the open tool is the honest-price option, not a compromise.
When does paying for the frontier CLI earn it?
When the specific work is the kind the open tools handle worst — the longest, most autonomous, multi-step tasks — and the markup you pay buys real throughput on those. For everything else, the markup is a rounding error against work the open tool already does.

The number on the bill

The comparison people run is capability against capability, and on that axis the open agent loses a little. But the line that decides the bill for most developers is not capability; it is the number that sits between you and the work. A frontier CLI is a per-seat subscription that runs whether or not you are productive in a given week. An open-source terminal agent has no such number: the tool is free, and the only charge is the inference — which you route to any provider's API, or to a local model where the marginal cost of a task is effectively zero. The open tool is not cheaper because it is weaker; it is the only one in the group that is priced at what it costs you.

The real gap, and how big it is

What the open tool actually trades away is a band of the most demanding autonomous work: the longest, most multi-step tasks where a frontier CLI's agent loop holds together further than the open equivalent. That is real, and it is the honest part of the comparison. But the width of that band is smaller than the price gap between the tools. Most of day-to-day coding is multi-file edits, refactors, tests and explanations, and on that work the open agent is competitive — especially when you point it at a strong model. The open tool's ceiling is lower; its floor, for ordinary work, is close to the paid one's.

When the markup earns it

Pay for the frontier CLI when the task that shows up in your week is precisely the one the open tool handles worst, and often enough that the markup buys genuine throughput. A team whose weekly work is the longest autonomous, multi-step runs is that case — the subscription is a rounding error against hours it recovers. A developer whose week is mostly ordinary multi-file work is the opposite case: the markup is real money, and the open tool already does the job for only the cost of the tokens. The decision is not which is better; it is which constraint — cost-per-task or ceiling-on-autonomy — is the one that actually bites in your week.
