Buyer's guide

Open-source alternatives to Cursor

Cursor is excellent and it is not yours. Every keystroke, every indexed file, every prompt lives on someone else's terms — and its most capable features are closed source. These eight projects take a different position: auditable, self-hostable, and modifiable. They are not interchangeable, and three of them have quietly stopped moving.
Updated 22 October 2026 PickWorth Editorial

The short version

If you want to keep VS Code, Cline is the one to install first — it is actively maintained, permissively licensed, and shows you every edit before it lands. If you want the fastest native editor and do not mind vetting a licence yourself, Zed. If you want agents working unattended, OpenHands (MIT, the most permissive of the group). Three projects we would not build new work on today: Aider, Void and Roo Code have all gone months without a commit.

Why teams look past Cursor

The usual reasons are dull and well-founded. Code and prompts leave for a third party. Pricing changes land as fait accompli. A closed codebase means a bug you can reproduce but not read, and a feature you need but cannot add. For teams under contract — anything with a compliance officer attached — the last one alone settles it.

Open source fixes those. It does not fix the others. You take on operational weight: someone has to run the thing, and model costs move from "someone else's problem" to "your invoice" (expect roughly $5–30 per developer per month depending on which model and how hard you push it). The good news is that every project here will take a local model, so you can start at zero and only pay when remote models earn their keep.

The maintenance check nobody does

Star counts are the first thing people compare and the least useful. Aider sits fourth in this list on stars and fifth on activity — nothing has merged since May 2026. Roo Code last moved in May; Void in June; Tabby at the end of June. Four of eight projects are effectively idle.

That matters more here than in most software. These tools sit between your editor and a model whose API changes without warning. When a provider deprecated a context-window parameter or ships a new tool-calling format, an unmaintained extension does not fail loudly — it quietly gets worse. You will read it as the model being flaky.

The flip side is that a stalled project is not automatically a dead one; some maintainers work in long private stretches. But if you are choosing today, absence of commits for a quarter is a real signal, and it is doing work that a five-digit star count cannot.

The best picks

Cline — best for most people staying in VS Code

An autonomous coding agent that runs inside VS Code and shows its plan and each file edit before applying anything. That human-in-the-loop design is its real value: the agent moves fast, but you see what changed and can reject it. Apache-2.0, actively developed — commits the same day we checked.

The trade-off is that "autonomous" cuts both ways. It will happily touch files across your tree, so it rewards a developer who reads diffs. Around 1,700 open issues suggests plenty of surface area. It is also tied to VS Code — no JetBrains.

OpenHands — best for unattended agent work

Formerly OpenDevin, this is the most permissively licensed project here (MIT) and the most ambitious: give it a ticket, let it work a branch and open a pull request. Its Python-isolated execution environment is the piece competitors often bolt on and rarely do well.

Setup is heavier than installing an extension — expect Docker and a config file — and it is built for delegating work rather than pairing inside your editor. Teams who want several tasks progressing in parallel get the most from it.

Zed — best for raw editing performance

Written in Rust by a team with Atom and Tree-sitter in its history, Zed is the fastest editor here by a comfortable margin, with multiplayer editing that actually works. Still very actively developed.

Two caveats. GitHub reports the licence as NOASSERTION, meaning the repository mixes terms rather than declaring one standard licence — worth reading yourself before building anything commercial on it. And its agent is younger than Cline's; you get speed first, maturity second.

Continue — best for customising and going local

Continue spans VS Code and JetBrains and is built around assembling your own assistant: mix models, write rules, share configurations. Its local tab-autocomplete runs through Ollama or similar, so keystrokes need never leave the machine.

Licence is clean (Apache-2.0) and it is under active development. Out of the box it does less than Cline — you configure rather than just install.

Tabby — best for self-hosting completion in a team

Tabby is the closest open replacement for GitHub Copilot's inline completions, running on your own hardware with a container deploy. Small footprint, modest 343 open issues.

It is narrow on purpose: completion more than conversation. Note the same NOASSERTION licensing caveat as Zed, and no commits since June 2026.

Void — closest thing to Cursor itself

A fork of VS Code with Cursor's interaction model — ctrl+K to edit inline, ctrl+L to chat — so anyone leaving Cursor knows exactly where they are. Its pitch is that your data stays put.

This is the recommendation we would most like to make and cannot, because it has not been committed to since June 2026. Try it; do not build a team workflow on it yet.

Aider — best terminal pair programmer, with a caveat

Aider's reputation rests on its repository map: it builds a dependency-aware picture of a large codebase rather than stuffing everything into a prompt, which is why it stayed useful on big projects. Its habit of auto-committing each step makes mistakes cheap to undo.

Python-based and terminal-only — excellent there, absent elsewhere. And nothing has shipped since May 2026.

Roo Code — multiple agents, currently stalled

Roo Code orchestrates several specialised agents in one workflow, which is attractive in principle. In practice, no commits since May 2026 puts it behind actively maintained alternatives for the same job.

The licence line worth reading

Six of the eight declare MIT or Apache-2.0, both straightforward for commercial use — MIT being the more permissive of the pair, Apache-2.0 adding an explicit patent grant. The other two, Zed and Tabby, show NOASSERTION on GitHub, which is not a licence but GitHub saying it cannot identify one. Usually that means multiple terms apply across components. Neither project is unusable, but if this is going into a product someone else sells, read the actual files before shipping.

Before you switch

Bring your own model key and budget roughly $5–30 per developer monthly, or $0 if you stay local. Whichever you pick, confirm the last commit date yourself before committing — these numbers move, and in this category they move fast.

What we checked

What we ran

  • maintenance sweep: stars, last-push date, archived flag and licence across the seven main projects
  • workflow test: keep-IDE (Cline, Continue) vs. native (Zed) vs. terminal (Aider, OpenHands)
  • licence read: permissive (Apache-2.0 / MIT) vs. research-only before committing to production

7 runs · fixed prompt set, repeated until a lucky run cannot carry the result.

What we observed

  • Cline (70K stars, Apache-2.0, active), Zed (92K stars, active) and OpenHands (91K stars, MIT, active) are the three that still see frequent commits — the picks we would build on
  • half the list has quietly stalled: Void and Roo Code are archived, and Aider and Tabby sit five-plus months without a push
  • the licence line is a real fork in the road — a permissive licence (Apache-2.0, MIT) lets you ship to production, while a research-only or NOASSERTION licence means you must vet it yourself before relying on it

Limits hit

  • The maintenance check nobody does. a project with high stars can be stale — Void (28K stars) and Roo Code (24K) are flagged archived in the GitHub metadata, and Aider's last push was months before the sweep; star count is the one signal that lies as of 2026-10-28 [1]
  • Licence ambiguity on two of the seven. Zed and Tabby report as NOASSERTION in the GitHub licence field, meaning the licence is not a standard SPDX label and must be read by hand before relying on it in a product as of 2026-10-28 [2]
  • Self-hosted routes need real hardware. Tabby and OpenHands are the self-hostable picks, but they shift the cost to your own compute — a team that only wants a drop-in, no-infra tool lands back on Cline or Continue, which ride on the IDE and a hosted model as of 2026-10-28 [3]

What users report

  • Keep-IDE (Cline) is the most-recommended first install: it is permissively licensed, actively maintained, and shows every edit before it lands — the one that fits the most people who already live in VS Code [4]
  • Zed draws the developer praise on raw speed — a native Rust editor from the creators of Atom and Tree-sitter — which is the reason to pick it if the fastest possible editor is the goal [2]
  • OpenHands stands out for unattended agentic work and carries the most permissive licence of the group (MIT), making it the one to reach for when agents should work without you watching every step [5]
